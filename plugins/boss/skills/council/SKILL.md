Run the plugin's own council runner at `${CLAUDE_PLUGIN_ROOT}/council/council.py`. This is a different command from `/octo:council` (the octo plugin); do not call or mimic that one.

`$ARGUMENTS` = optional leading flags (`--allow-missing <provider>`, `--context-file <file>`, `--rulings-file <file>`, `--config <overlay.toml>`, `--allow-paths`, `--lenses on|off`, `--lens <seat>=<text>`, `--grounded [<dir>]`, `--attach <image>`, `--depth quick|standard`), then the question. Pass every flag to `ask` as given. What a flag does: `council.py ask --help` (free, prints only text). Hand re-reads of a run, drift accepts, orphans and the runner: [reference.md](reference.md), read only when you need it.

1. **Question.** If the question is empty, ask for it with AskUserQuestion and stop until you have it. Write it verbatim to a private file so quoting cannot change it: `Q=$(mktemp)` then `cat > "$Q" <<'COUNCIL_QUESTION_END'` ... `COUNCIL_QUESTION_END`.
   - **Attach every file the question refers to.** Seats run in a temp cwd with the prompt on stdin: they cannot read disk, so "read it from disk" or a bare path gives them nothing. For each file the question names or relies on (absolute, `~/...`, or a file in a directory it names), add `--context-file <absolute path>` (repeatable; check each exists). A named directory is covered once at least one file under it is attached: attach the ones that matter, not the whole tree. A path in the question that is not attached is a `question_path` FAIL: add the `--context-file` and run again; do not reword the question to hide the path. Add `--allow-paths` only when a path is illustrative (an example, a log line). With `--grounded`, a path inside the grounded root needs no `--context-file` for the seats that can read it (attach it too when the ungrounded seats matter).
   - **Settled rulings.** When owner rulings bear on the question (an orchestrator run's rulings, rulings given in this chat), write a scrubbed excerpt to a temp file and pass `--rulings-file <file>`. Scrubbed means: only the rulings that bear on the question, each as one plain sentence of the decision itself, with no names of people or employers, no addresses, no application or account details. The engine sends it to every seat and the chair under its own heading, "settled; raise only if you find a defect". Never attach a rulings or memory file whole (`DECISIONS.md`, `MEMORY.md`, a `.claude/projects/*/memory/` file): every form refuses it (`ask` and `run` with exit 2, `preflight` with a FAIL row). By name always; a renamed copy only in part, when its content still has that file's shape (a copy with a line put in front, a short one, or a memory note without frontmatter passes): never pass a copy under another name, write an excerpt. Every form also refuses a rulings file holding an email address, a URL, a home-directory or memory-folder path, a key-shaped string or a phone number (it names the line and the kind: fix those lines and run again). These checks are a backstop and never see names, employers or figures: the excerpt you write is the real guard.
2. **Ask** (one call: the preflight, the run and the report): `${CLAUDE_PLUGIN_ROOT}/council/council.py ask <flags> --question-file "$Q"` with `run_in_background: true`. A council takes minutes and every seat is a paid call: wait for the completion notice, don't poll, and never kill or cap a seat, the runner or its calls (the manual stop is in reference.md; use it only when the user asks).
3. **Exit codes** (report the code in words):

   | code | meaning |
   |---|---|
   | 0 | done, also below quorum (say the synthesis rests on fewer answers than the quorum asks for) |
   | 1 | a preflight FAIL: the table names it; no run dir, nothing was sent. Stop: do not retry, do not drop a provider yourself (only the user's `--allow-missing` may) |
   | 2 | usage or policy, a refused rulings file or a whole rulings/memory file: show the error and stop |
   | 3 | quorum not met, no chair ran: point at `<run dir>/seats/` |
   | 4 | either the chair failed (its one salvage call too; seat answers are kept) or `pending: no answers yet` (the chair runs when the first answer arrives): say which |
   | 5 | the runner crashed before the synthesis: read `<run dir>/runner.log`, say it was a crash and not a preflight failure, do not retry blindly |
   | 128+N | the launcher got signal N (143 = a manual TERM); the runner and its calls keep running and the results still land in the run dir |
4. **Report.** Relay the output, in its order:
   - The preflight rows it prints. A WARN never stops the run. **Name every WARN row in your reply**: each `drift:<item>` change, each `orphan:` row (a `LIVE` orphan is a paid call still running with no supervisor: name seat, call, run and age; only the user may stop it), each seat that runs as its stand-in, each `ungrounded` seat (its claims about the source are unchecked), each `question_path` WARN. With `--depth standard`, show the `depth` row and say the run costs about 2N+1 calls.
   - `run`'s own lines (`synthesis ready`, `below quorum`, `pending seats`, `pending: no answers yet`, `still running`, `run dir:`, `exit:`): repeat each.
   - The block between `== council report` and `== end of report ==`: the per-seat table, then say in words the cost (`cost_reported_usd` and the calls in `cost_unreported`: the real total is higher by their spend), every non-empty calls/phase field, the critique and the quorum. **Say every flag and every preflight notice the block lists**, and that a council with flagged seats is weaker than its seat count. Verdicts are display only: not a vote, not a gate; never stop, retry or reweigh because of one; report the tally when a seat said REVISE or BLOCK. On a critique run, quote the part of the synthesis that says which critiques changed the recommendation.
   - The synthesis path and its first lines from the block, then read the rest of `chair/synthesis.md` (Minority view, Risks and unknowns, Implementation path, Confidence, Next step) rather than stopping at the recommendation. The summary is a snapshot: late answers are appended to the synthesis later, flagged and not used by the chair.
5. **Rules.** Never simulate or write a seat's answer yourself. Never substitute another model for a failed seat. Never `pkill -f`; if something must be stopped, kill the PID or process group you started. Never print key values, and never put one in the question, a context file or the rulings file. The block's last line is the leaked-key scan of the run dir; for a hand check run `bash ${CLAUDE_PLUGIN_ROOT}/council/tools/secret-scan.sh <run dir>` (exit 1 lists files with key-shaped strings, never the strings). Remove the question file and the rulings excerpt when done (`rm -f "$Q" <rulings file>`).
